# v0.4.1

Changes since `v0.4.0` for the `v0.4.1` release.

## Terminal UI and CLI

- An optional terminal dashboard provides progress, interactive forms, and results. Select `--ui=tui` explicitly or `--ui=auto` for automatic terminal detection. Plain output remains the default; `--ui-keep-open` keeps the dashboard open after completion.
- Input identifies missing Category, Type, Source, and Resolution before upload and lists the required corrections. Confirming metadata cannot bypass missing facts. Strict `--unattended` reports them without prompting.
- `--console-log-level` changes terminal verbosity independently of application logs. Terminal diagnostics are bounded, and credential and private-endpoint redaction is improved while preserving useful local filesystem paths.

## HDR analysis

Follows Azure work from [HDR-Checks](https://gitea.okami.icu/azure/Release-Guide/wiki/HDR-Checks).

- HDR10+ and Dolby Vision analysis is available in the CLI and Web UI. The default mode generates native metadata plots and primary-audio waveforms, spectrograms, and statistics without decoding video.
- Optional picture analysis includes bounded scene synchronization, sampled or full-frame measurements, active-area border checks, and comparisons against a manually aligned reference source. Sampled and bounded checks can miss brief mismatches; an inconclusive result is not a pass.
- Compatible retained metadata and measurements can be reused for rendering and retries. Successful artifacts remain available from partial results. Native plots and audio results can be included in descriptions; picture-check images require explicit selection and do not consume ordinary screenshot slots.
- Use `--hdr-analysis` during upload preparation, or `--hdr-analysis-only` with `--hdr-output-dir` for standalone reports. See [HDR analysis](../workflow/hdr-analysis.md) for source requirements, modes, and coverage limits.

## Metadata, languages, and naming

- Source-wide review collects missing programme-track languages and soundtrack origin once across selected trackers. `--track-languages` and `--track-audio-origin` provide separate corrections for language and original, dubbed, or unresolved soundtrack status. Commentary is excluded from programme soundtrack classification.
- 3D and presentation corrections are independent of Edition. `--3d` and `--3d=false` set or clear effective 3D, while presentation and release-feature controls retain their separate meanings.
- Automatic Hybrid, restoration, remastering, extras, and packaging annotations remain separate from edition identity. Generic remastering evidence no longer implies a 4K remaster.
- Explicit season-zero specials survive parsing and naming. Sources containing files from multiple seasons receive a warning for review.
- Naming fixes preserve release versions and source downscale evidence, correct audio markers, and improve DVD encode names.

## Tracker preparation and duplicate checks

- Expanded [tracker support](../trackers/supported.md) and improved upload compatibility, eligibility checks, naming, and duplicate searches.
- A naming failure blocks only the affected tracker, allowing other selected trackers to continue preparation and duplicate checks.
- Questionnaire follow-ups refresh affected CLI stages, and ineligible trackers no longer ask unrelated questions. Interactive yes/no questions also accept `y` and `n`.
- Warnings that require review remain actionable even when a duplicate search finds no matching releases. Compatible acknowledgements survive equivalent metadata refreshes.

## Web UI, screenshots, and workflow

- The Web UI source browser supports bounded recursive searches across authorized browse roots.
- Imported screenshot-link acceptance is retained with matching source and prepared-generation evidence. Existing links without that evidence remain unknown, and a new or corrected generation requires fresh matching evidence.
- Screenshot tonemapping status follows the exact image content and hosted link through saving and reuse. Changed image bytes or unrelated links cannot inherit processing evidence from current preferences or another image.
- Explicitly skipping image hosting also prevents auxiliary uploads during content preparation.
- Startup closes the previous active input while preserving workflow checkpoints and uncertain remote outcomes. Check tracker and client results before retrying an interrupted submission.

## Configuration and torrent clients

- `--export-config` works on a fresh installation by exporting built-in defaults when no configuration has been stored.
- Direct qBittorrent connections accept empty credentials when the server permits authentication bypass for upbrr's address. Empty fields do not enable bypass on the server.
- Reusable torrents discovered from clients retain their exact metadata, preventing another source with the same name from overwriting the captured torrent and avoiding unnecessary rehashing.

## Upgrade and compatibility notes

- Back up the whole state directory with every upbrr process stopped. This release adds forward-only database migrations for imported screenshot-link acceptance, screenshot content and tonemapping provenance, and retained HDR analysis associations. Restore the matching backup before returning to `v0.4.0`.
- Older prepared snapshots require preparation again. Review generated names, language and soundtrack classifications, tracker questions, descriptions, and payloads before the first live upload after upgrading.
- The CLI `--title` and `--original-title` corrections have been removed. Title and original title come from metadata providers; use `--alternate-title` for an alternate-title correction.
