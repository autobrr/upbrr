# Upcoming v0.4.2: release artifacts

Automatically managed release files are kept together under `tmp/<release>/` in the active state directory. The primary `mediainfo.txt` and `MediaInfo.json` are stored at that release folder's root; secondary inspections, analysis outputs and temporary work stay beneath the same owner. Source validation still controls reuse. Deleting a release from History removes its owned generated files, including nested outputs, while preserving active or shared artifacts and source media.

Older prepared releases require preparation again. There is no automatic migration or discovery and cleanup of the previous report-cache layout.

## Remove the legacy report cache

1. Stop every upbrr binary, service and container using the state directory, including scheduled restarts.
2. Locate the **active state directory** using [Configuration: State location](../configuration/index.md#state-location). Check any configured state-path override or container volume; do not assume the current working directory is the state directory.
3. If that state directory contains `tmp/hdr-mediainfo`, verify that it is the old upbrr report cache before manually removing **only that directory**. If it is absent, skip this step. Do not remove all of `tmp`, the state directory, its database, authentication/configuration files, or source media.
4. Install the new version, start upbrr and prepare releases again to recreate validated reports in their release folders.

Follow the [upgrade procedure](../getting-started/upgrading.md), including a stopped-service state backup before upgrading.
