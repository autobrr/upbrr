# v0.4.0

Changes since `v0.3.5.1` for the `v0.4.0` release.

## CLI and Input corrections

- `-hc` accepts subtitle languages and coverage: `-hc English Forced` or `-hc Spanish`. Use `-hc="Custom Dialect"` for a multiword custom language. Bare `-hc` retains the hardcoded-subtitle indication and can require tracker questions; it does not guess a language.
- `--season` now accepts exactly two or four digits, optionally prefixed with `S`: use `05`, `S05`, `2026`, or `S2026`. One-digit seasons and `1x02`-style automatic season detection are no longer accepted. `--episode` remains separate.
- Year-numbered seasons are supported in release names and tracker duplicate searches.
- `--category TV` takes precedence over a parsed Movie classification when acquiring TVDB metadata. Explicit Movie corrections continue to prevent TVDB acquisition.
- `--type` corrections determine video naming, including the appropriate encoded-video or source-codec form, without being replaced by inferred source type.
- `--log-level` applies throughout a run, including asynchronous work and continuation. It changes logging only; `--debug` remains the separate non-submitting workflow mode.
- Input offers searchable correction choices and a **Release version** control independent of **Edition**.

## Metadata and naming

- TV category detection uses supported source-folder and filename context without inserting parent-folder text into the release title.
- Matching metadata lookup evidence is reused when corrections do not change its dependencies, reducing unnecessary repeat provider requests.
- Explicit tracker IDs can supply metadata for a fresh source, including its imported description and image references.
- Release cut, presentation, and edition-set details are retained as separate facts for tracker naming; manual edition text remains authoritative.
- Canonical DVDRip names include resolution. Confirmed scene release-group capitalization is retained.
- Effective anime corrections are reflected in prepared media facts.

## Tracker questions and duplicate checks

- Tracker questionnaires appear on Dupe Check as soon as the selected tracker and available release facts require them. Panels start collapsed, and answers remain editable.
- Answer-only changes retain compatible duplicate results rather than forcing another remote search. Changed release or tracker context still requires fresh assessment where relevant.
- Tracker warning acknowledgements use the same review flow across CLI and Web UI.

## Workflow, media, and configuration

- The Web UI preserves in-progress edits across background updates, makes saved-correction review actionable, and improves image preview and lightbox handling.
- Imported tracker descriptions and screenshots remain available during preparation, including validated image references for screenshot reuse or rehosting.
- Incremental screenshot capture preserves earlier selection and order without adding existing captures again. Uploaded audio-analysis images remain available after restoring saved work.
- Saved final description edits retain their output and tracker applicability when restored.
- Startup marks unfinished operations interrupted after prior leases expire and retains completed checkpoints. Work awaiting feedback can be continued explicitly. Check remote tracker and client outcomes before retrying: a failed local record does not prove a remote action failed.
- Upload Assistant imports accept type-annotated `config` assignments and skip unused incomplete client examples with warnings. Referenced incomplete clients still require correction.
- Eligible same-repository pull requests publish an amd64 `pr<number>` Docker testing image after a successful build; Dependabot runs remain build-only. Use separate test state when trying a development image.
- Frontend and image-decoding dependencies include available security fixes.

## Upgrade notes

- Back up the whole state directory with every upbrr process stopped. This release includes forward-only database changes for metadata evidence, release cuts, and retained media details. Restore the matching backup before returning to an older binary.
- Older prepared snapshots may need preparation again. Review generated names, tracker questions, descriptions, and payloads before the first live upload after upgrading.
